# 岗位数据清洗规范

> 用途：自动化同步脚本（飞书多维表格 → MySQL）在增量写入前，按本规范清洗每条新数据。
> 数据流向：飞书表原始行 → 逐字段清洗 → 写入 `campus_job` 库 `job` 表。

---

## 一、目标表结构（job 表，19 个字段）

| 数据库字段 | 类型 | 说明 |
|---|---|---|
| `publish_date` | DATE | 网申更新日期 |
| `company_name` | VARCHAR | 公司名称 |
| `industry` | VARCHAR | 标准行业（逗号分隔多值） |
| `industry_raw` | VARCHAR | 原始行业 |
| `recruit_types` | VARCHAR | 标准招聘类型（逗号分隔多值） |
| `recruit_type_raw` | VARCHAR | 原始招聘类型 |
| `company_nature` | VARCHAR | 标准企业性质 |
| `company_nature_raw` | VARCHAR | 原始企业性质 |
| `target_raw` | VARCHAR | 原始招聘对象文本 |
| `grade_min` | INT | 届别下限（不限届=0） |
| `grade_max` | INT | 届别上限（不限届=99） |
| `education` | VARCHAR | 最低学历要求 |
| `positions` | TEXT | 招聘岗位（逗号分隔） |
| `cities` | VARCHAR | 工作地点（逗号分隔，已归一化） |
| `notice_url` | TEXT | 网申公告链接 |
| `apply_url` | TEXT | 投递链接 |
| `deadline` | VARCHAR | 截止说明文本 |
| `deadline_date` | DATE | 截止日期（可解析时） |
| `remark` | TEXT | 备注 |
| `status` | TINYINT | 状态（新增默认 1=上架） |

## 二、逐字段清洗规则

### 1. publish_date（网申更新日期）
- 统一格式 `YYYY-MM-DD`（处理 `2026/8/19`、`2026年8月19日`、Excel 日期序列等）。
- 空值 → NULL。

### 2. company_name（公司名称）
- `trim` 去首尾空格。

### 3. industry（行业）→ 标准值 + 原始值各存一份
- **先做错别字纠正**（见「通用错别字纠正表」）。
- 映射到 **18 个标准大类**，无法识别的归入「其他」：
  ```
  互联网/软件/游戏、电子/半导体/通信、智能硬件/机器人、机械/制造/汽车、
  金融、银行、咨询/财会/法律、传媒/文化/出版、教育培训/科研、医疗/生物医药、
  能源/化工/环保、建筑/地产、交通运输/物流、消费品/零售/快消、
  政府/事业单位/公共服务、国防军工/航空航天、农业/农林牧渔、其他
  ```
- 原始行业是「多值」（逗号分隔）时，逐个拆分映射，去重后逗号拼接。
- 原始值原样存 `industry_raw`。

### 4. recruit_types（招聘类型）→ 标准值 + 原始值
- 先错别字纠正，再按 `, ， 、 /` 拆分多值。
- 映射到 **12 类**，并按下面顺序排序：
  ```
  秋招提前批、秋招、春招补招、春招、暑期实习、寒假实习、
  日常实习、实习、转正实习、校园大使、商赛/训练营、社招
  ```
- 原始值存 `recruit_type_raw`。

### 5. company_nature（企业性质）→ 标准值 + 原始值
- 先错别字纠正，映射到 **6 类**：
  ```
  民企、央国企、外企/合资、事业单位、社会机构/公益组织、其他
  ```
- **银行、金融类统一归入「央国企」**。
- 原始值存 `company_nature_raw`。
- **同名公司众数归一化**：同一公司多条记录若性质不一致，取出现最多的性质（并列时按「央国企 > 事业单位 > 社会机构 > 民企 > 外企/合资 > 其他」优先级）。

### 6. target_raw + grade_min/grade_max（招聘对象 → 届别区间）
- 原始文本存 `target_raw`。
- 从文本提取 **21~30 之间的数字**作为届别：`grade_min = 最小数字`，`grade_max = 最大数字`。
- 含「不限」→ `grade_min=0, grade_max=99`。
- 无法解析（如「往届生」「研究生」「留学生」）→ grade_min/grade_max 均为 NULL。

### 7. education（学历）→ 存最低学历
- 映射到 6 档：
  ```
  不限、高中、专科、本科、硕士、博士
  ```
- 「本科起」「大学生」→ 本科；「硕士起」→ 硕士；「详见公告」「不限学历」→ 不限。

### 8. positions（招聘岗位）
- 分隔符（`, ， 、 ; ；`）统一为英文逗号 `,`（便于后端 `FIND_IN_SET` 筛选）。
- 去掉每个岗位名末尾的省略号 `..`。

### 9. cities（工作地点）→ **重点归一化**（见下方专节）

### 10. notice_url / apply_url（链接）
- `trim`，原样存。超长（>255 字符）存 TEXT。

### 11. deadline + deadline_date（截止）
- 文本存 `deadline`，解析出的日期存 `deadline_date`。
- 「招满即止 / 尽快投递 / 额满即止」→ `deadline="招满即止"`，`deadline_date=NULL`。
- 支持格式：`2026/8/19`、`2026年8月19日`、`2026/8`、`8月19日`、`8月底`（→8月30）、`8月初`（→8月1）、`8月中旬`（→8月15）。
- 无法解析 → `deadline` 存原文，`deadline_date=NULL`。

### 12. remark（备注）
- `trim`，原样存。

## 三、城市归一化（cities 字段，最重要）

城市原始数据很脏（1080 个变体），必须归一化。**按以下顺序处理每个城市值**：

1. **去空格**（含全角空格），`trim`。
2. **错别字纠正**（精确匹配）：`成部→成都`、`夏门→厦门`、`里庆→重庆`、`东芜→东莞`、`北惊/北凉→北京`、`何北→河北`、`内蒙→内蒙古`、`浦东→上海`、`雄安新区→雄安` 等。
3. **归类判定**（按优先级）：
   - 含「远程/线上/在线」→ `远程/线上`
   - 含「全国/全球/各地/各省/主要城市/多城市」→ `全国`
   - 大区（华东、华南、珠三角、长三角、大湾区、川渝 等）→ `全国`
   - 国家/外国城市（美国、日本、德国、东京、伦敦、新加坡…）→ `海外`
   - 明显非城市（服从调剂、未注明、未知、根据…分配、总行/网点/驻场 等）→ `其他`
4. **后缀归并**：去掉「市/区/县/镇/乡/村/旗/盟/州」后缀，再去白名单匹配。
5. **前缀归并**：
   - `省+市` → 市（`山东济南`→`济南`、`湖南长沙`→`长沙`）
   - `直辖市+区` → 直辖市（`北京海淀区`→`北京`）
   - `城市+区/县` → 城市（`深圳福田区`→`深圳`、`宁波象山`→`宁波`）
6. **白名单匹配**：命中中国地级市/直辖市/港澳台/省级/常见县级市 → 保留。
7. 其余 → `其他`。

**归一化后城市的合法集合**（约 350 个）：
- 中国地级市 + 4 直辖市 + 港澳台 + 27 省级
- 特殊归类：`全国`、`海外`、`远程/线上`、`其他`

**去重**：同一行多个城市归一化后去重，逗号拼接。

## 五、清洗完存哪

- **数据库**：服务器 MySQL `campus_job` 库，表 `job`（端口 3306，账号 root）。
- **唯一键去重**（增量判断）：`company_name + positions + publish_date` 三者组合相同视为同一条，不重复插入。
- **status**：新写入的记录 `status=1`（上架）。
- 增量流程：飞书表全量记录 → 逐条清洗 → 与 `job` 表已有记录按唯一键比对 → 只插入新增的。

## 六、参考实现

- 全字段清洗：`scripts/clean_data.py`（处理原始 Excel）
- 城市归一化：`scripts/normalize_cities.py`（可直接复用，含白名单和规则）
- 建表 SQL：`data/schema.sql`

> 建议：自动化同步脚本直接 import `normalize_cities.py` 的 `normalize_city()` 函数做城市归一化，其他字段照本规范实现，避免手工重复维护规则。
