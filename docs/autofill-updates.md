# 客户端填写助手与独立脚本更新

客户端首次升级后，可通过独立脚本更新迭代字段映射、模块面板、站点及控件适配，不需修改 Vue 或重新打包。新增原生能力、通信协议、新简历数据库字段仍需相应开发及可能的客户端升级。

客户端 0.1.9 的引擎来自浏览器插件的共用模块，`autofill.js` 是生成文件，不再直接手工维护。修改 `autofill-extension/fields.js`、`controls.js`、`engine.js` 及相应站点适配器；客户端专属界面与原生 AI 桥接位于 `campus-job-desktop/src-tauri/autofill-desktop.js`。运行 `node scripts/build_desktop_autofill.cjs` 生成内置脚本，正常客户端构建也会自动执行。构建模块顺序读取插件 manifest，保留第三方 MIT 许可与来源说明。

## 数据协议 1

主界面加载本账号完整简历列表及字段 schema，交由原生进程注入 `window.__RESUME_DATA__ = {protocol:1,schema,resumes:[...]}`。现有原生 AI 桥接使用注入的当前账号凭证，请求经客户端转发；AI 服务密钥不下发客户端。仅发送字段名称、控件类型及候选项元数据，不发送简历值。退出登录清空简历；编辑保存后同步已打开网页并通知 `xiaomai-resume-updated`，执行中的填写会停止，避免混用新旧资料。

共用 `XiaomaiFields` 配置与识别字段归属、数据属性、中文名称及匹配别名，并读取服务端动态 schema。`XiaomaiEngine` 执行控件操作并复核可观察结果，不能仅设置文本就假定招聘系统保存成功。适配函数不应提交表单或读取账号凭据。

目前复用插件的输入框、多行文本、原生下拉、单选/多选、日期、Element/Ant 下拉与级联、虚拟候选列表，以及 Wintalent/Phoenix 适配器。先展开并等待真实候选项，仅搜索型控件使用远程搜索，唯一匹配后选择并复核。重复经历默认按网页记录序号匹配，不会用第一段资料补缺；手动指定经历时需仅展示一组目标表单。跨域 iframe 与所有招聘网站的兼容性没有全覆盖保证。

## 发布

1. 修改共用模块或客户端面板的 VERSION，执行 `node scripts/build_desktop_autofill.cjs`，运行插件与客户端测试，并在目标网站人工验证。
2. `node scripts/build_autofill_release.cjs 1.0.0` 生成 `output/autofill-release/autofill/`。
3. 将带内容哈希的 releases 文件上传至站点静态目录 `/opt/campus-job/app/autofill/releases/`，再原子替换 `/opt/campus-job/app/autofill/manifest.json`。禁止先发布清单再上传脚本。
4. 检查 `https://my88ai.com/autofill/manifest.json` 与清单中的脚本地址均可下载，文件 SHA-256 一致。该目录不包含简历、密钥或登录信息。
5. 用户新开网申页签时检查更新；已打开的页签继续使用原脚本，关闭重开生效。更新不在填表过程中替换脚本。

下载走原生 HTTPS，固定官方域名、不接受重定向，限制请求超时和文件大小。SHA-256 校验用于一致性与缓存损坏检测，真实性依赖官方 HTTPS 服务，不等价于独立数字签名。失败使用已校验缓存，无缓存时用内置脚本。初始化语法或同步启动异常回退内置版本；异步或业务逻辑缺陷仍需测试及回滚。

更新文件会保存在应用缓存目录的 `autofill-v1.json`，不保存简历。临时断网仍可使用缓存的填写逻辑。

## 回滚与停用远端更新

- 回滚：将清单指回保留的上一版脚本路径与哈希；下次新开页签生效，允许回滚到较低版本号。
- 紧急恢复内置脚本：清单保留其他字段，设置 `disabled:true`；客户端成功读取后删除本地更新缓存并使用内置脚本。
- 修改静态网页部署流程时保留 `/autofill/` 目录，防止普通网页部署误删填写脚本。

2026-10-12：客户端 0.1.9 同步插件 0.1.8 的共用引擎，脚本版本 1.3.0 已发布。网页版与脚本采用 `scripts/deploy_desktop_web.sh` 发布；发布目录保留旧入口与旧清单，旧哈希资源和历史脚本不会删除。客户端面板默认右侧居中收起，支持拖动、自定义简历/模块选择、逐字段进度、覆盖确认与结果核对。
